# 走向成熟的 Linux 输入平台

[English](../platform-roadmap.md) | 简体中文

分析基线：2026-11-24，源码版本 0.5.0。本文区分已实现原生入口与待完成验收，真实应用观察结果记录在[应用兼容性](compatibility.md)中。

Windows TSF 与 macOS InputMethodKit 提供相对统一的系统入口。Linux 需要针对不同合成器、工具包和显示协议实现多条入口，并让用户获得一致的输入体验。oh-my-ime 已具备独立引擎进程、按应用记忆、引擎恢复、UI Bridge、设置、托盘、安装包和回归测试。主要差距是桌面覆盖、真实应用验收，以及从安装到故障恢复的完整操作路径。

## 能力差距

| 能力 | 体验目标 | 当前基础 | 需要补齐 |
|---|---|---|---|
| 桌面接入 | 系统能发现并启用输入法，登录后可用 | Hyprland/sway IM v2、KDE IM v1、GNOME 系统 IBus；XWayland 入口 | 实际桌面与应用矩阵验收；纯 X11 |
| 应用覆盖 | 浏览器、终端、编辑器、办公软件组合输入一致 | 合成客户端回归；sway 上 Firefox、foot、xterm 有限场景证据 | GTK 3/4、Qt 5/6、Chromium/Electron、VS Code、WPS、WeChat 分别验收，覆盖沙箱包与启动器 |
| 候选窗 | 跟随光标、屏幕边缘可见，缩放后显示与点击正确 | 引擎独立 UI、Wayland UI Bridge、X11 光标镜像 | 各后端混合 DPI、全屏、屏幕边缘与实际显示器验收 |
| 文本编辑 | 上屏、选区替换、删除和切焦点均正确 | 有序 Commit、Preedit、DeleteSurrounding；有界输出队列 | 适配器字节/字符边界、serial、上下文生命周期；重转换设计 |
| 故障恢复 | 故障后继续打字，说明可指导操作 | 按键超时、重启、隔离和诊断 | 桌面重连与长时间运行验收；图形恢复入口 |
| 首次使用 | 选择语言、启用输入法、试打并完成 | CLI setup、语言建议、输入法排序 | 桌面识别图形引导、试打反馈、易懂的应用修复 |
| 视觉交互 | 导航清晰、状态易读、主题一致、键盘可操作 | Slint 设置/切换浮层、中英文 | 统一组件、小窗口与长文本布局、焦点和读屏验收 |
| 引擎生态 | 安装、升级和接入接口稳定 | manifest、Rust SDK、Python/GTK 示例、托管 Fcitx5/IBus | 更多引擎接入协议 1.3 候选语义、SDK 示例、来源与版本管理 |
| 性能资源 | 时延稳定，长期运行资源不持续增长 | 超时、队列上限和资源回归 | 各入口 p50/p95/p99 时延与内存基线、休眠恢复、长期输入测试 |

预测、词库、语音和手写可以由引擎提供。平台负责接入、焦点、送达、展示、恢复与管理；完善基础能力，才能容纳更多有不同 UI 的引擎。

## 架构边界

核心引擎监督、设置和控制服务由各入口共享。Wayland 自动选择 IM v2 + virtual keyboard，
或 KWin 特权连接的 IM v1 + input-panel-v1。GNOME 的 `--ibus` 模式无需 Wayland 输入连接，
把 oh-my-ime 注册为现有系统 IBus 中的引擎。

KDE 按 commit_state 同步文本状态，保留原始键盘 serial，候选 surface 与文本协议共用
特权连接。GNOME 转换 UTF-8 字节边界与 IBus 字符偏移，对输入输出限流，失焦后使待发
内容失效；密码/PIN 及 PRIVATE/HIDDEN_TEXT 字段绕过引擎。

协议 1.3 提供可选候选语义、选词和翻页回调。Rime 的 IBus 模式无头运行，由 Shell 绘制
候选窗。Wayland 后端仍支持引擎自绘 UI。托管框架与 GNOME 系统 IBus 引擎模式分别管理。
使用方法见[原生桌面接入](native-desktops.md)。

## 当前实现批次

1. setup 自动识别桌面，也可显式选择 Hyprland/Sway；管理可撤销的 Sway 配置、启动项与输入环境，兼容旧 Hyprland journal，避免静默配置错误桌面。
2. 守护进程与 CLI 诊断共用协议能力判定，具体说明缺少的支持。
3. 重设原生 Slint 导航、字号、卡片、深浅配色和状态展示，保留现有控制功能。
4. 私有会话验证 Sway 预览、配置语法、重复执行、撤销与首次输入，保留 Hyprland 和输入回归。

5. 完成 KDE IM v1/panel、GNOME 系统 IBus、协议 1.3 候选、Rime 无头展示、可撤销原生配置与 Nix 后端选择。
6. 在隔离环境运行真实 KWin、IBus、Shell 验收，分别记录协议正确性、合成输入和实际显示器结果。

Sway 直接启动的应用仍需在会话启动前继承输入环境。KDE/GNOME 原生配置使用桌面自身的
启动与工具包环境。

补齐图形首次使用、试打和恢复，支持纯 X11，验收更多 IM v2 合成器。建立混合缩放、可访问性、休眠恢复和资源基线。公开适配器/引擎能力约定，让界面准确解释未支持的功能。

## 每条输入入口的验收标准

| 场景 | 可观察结果 |
|---|---|
| 组合输入 | 编辑预编辑、翻页、选词后只上屏一次；中英混排顺序正确 |
| 焦点变化 | 切换输入框/应用、关闭窗口后不泄漏旧文本和候选窗 |
| 普通按键 | 未处理按键、快捷键和释放事件到达应用，无粘住的修饰键 |
| 文本操作 | 插入、替换选区、删除周围文本保持 Unicode 边界正确 |
| 候选窗 | 光标跟随、边缘、移动、缩放与点击命中正确 |
| 敏感字段 | 报告密码/PIN/敏感用途的入口绕过引擎；缺少元数据时记录限制 |
| 服务恢复 | 分别重启引擎和守护进程，普通键盘可用，组合输入恢复 |
| 安装启用 | 新登录可启用；撤销恢复原配置；终端和启动器内应用行为一致 |

报告使用 `passed`、`failed`、`blocked`、`not-tested`，记录应用/桌面版本、入口、引擎/方案和证据。协议回归不代表所有应用通过；无头测试不证明实际显示器或启动器行为。

## 验证历史

2026-11-24：原生批次通过 Rust 格式、严格 Clippy、工作区构建与测试（含 167 项 omimed
测试）、翻译覆盖、42 项打包/脚本测试、8 项桌面探针测试和 cargo-deny 检查。
隔离原生探针通过 KWin 6.8.3（6 项）、GNOME Shell 50.4（8 项）、IBus/Rime（6 项）
和 IBus/Echo（5 项）。证据路径与限制记录在[桌面和应用验收](compatibility.md)。

可选旧 E2E 的 setup、Sway、管理、托盘和 Wayland 分组通过；XIM/Fcitx5 分组因本运行器的
`/tmp/.X11-unix` 所有者不是 root、XWayland 无法启动而阻塞。这是运行环境前置条件，
不是 KDE/GNOME 原生入口失败；请在 CI 桌面环境重新运行。

设置界面使用 AGY `gemini-4-hydrogen-high` 生成，经 Slint 审查和修正，
在独立 sway/D-Bus 会话中连接真实 omimed/Rime 截图。查看[浅色](../images/settings-light.png)、
[深色](../images/settings-dark.png)与[紧凑窗口](../images/settings-compact.png)。
这些 UI 检查不代表实际显示器或启动器验收。
